# healthOS Audit Report — 2026-05-09

## 1. Headline state (5 sentences max)

The repo is a real Python ingest → scorer → trends/interventions → `snapshot_builder` stack plus a polished Vite/React front-end; the demo pipeline completes successfully when `RAWDATA_ROOT` points at `data/examples/alex_demo` (same sequence as `Makefile` `demo`, minus the non-terminating dev server). The **NLR×HRV flagship is effectively dead on the public demo**—the latest generated snapshot shows **0 valid wake-HRV baseline days**, so C1 stays `unknown` while SRI is real and aerobic decoupling stays `unknown` for lack of z-score history. Composite logic therefore lands on **`accumulating-fatigue` (score 38)** with **~0.1% confidence**, not the clean `insufficient_data` gate you get only when **all three** lenses are unknown—this is confusing UX vs the written composite spec narrative. Documentation and several spec headers are **materially stale** (NLR spec claims “no implementation,” composite module docstring claims SRI/EF unwired, `divergence-analysis.md` still describes an old “89 recovered” world). For a **~3h YC submission**, the smallest fixes are: **refresh docs/spec headers to match code**, **either fix HRV coverage in `alex_demo` or lead the demo narrative with data-coverage honesty**, and **align snapshot headline state with `insufficient_data` when the wedge metric is silent** (spec + builder), then rerun pipeline + `npm run build`.

## 7. Risks ranked by severity

### BLOCKING (project cannot ship)

1. **Demo destroys the core wedge story unless reframed:** `alex_demo` snapshot after full pipeline shows **NLR×HRV unavailable** (no usable wake HRV series in-ingest for baseline). A “multi-source fusion” demo that **cannot show NLR×HRV** is a credibility hazard for YC reviewers expecting the flagship.

2. **`evals/run_eval.py` systematically mis-tests the shipped system** by **dropping SRI + aerobic scorer outputs** → forces **`insufficient_data`** and **zero-variance predictions** → correlations undefined **by construction**, not physiology.

3. **LICENSE file missing** while README claims MIT — legal/operational **blocking** for public distribution polish.

### DEGRADING (project ships but YC submission is weakened)

1. **Docs/spec headers contradict the running code** (NLR spec status, composite header comments, snapshot_builder hints, divergence-analysis vs divergence-report). Undermines “spec-first senior judgment” narrative.

2. **README “Getting Started” Python snippets reference non-existent APIs** (`load_zepp`, `generate_monthly_report`) — looks junior if someone clones and pastes.

3. **`make demo` does not run `npm run build`** — easy to demo broken front-end while Python “works.”

4. **Only two interventions** emitted for the demo date — “top-3 levers” chapter is thin.

5. **SRI / aerobic scorers lack dedicated unit tests** (unlike NLR/composite/bio-age).

6. **`divergence-analysis.md` false history** — if included in submission packet without update, it **contradicts** the repo.

### COSMETIC (nice to have)

1. Vite bundle **>500 kB** warning.
2. `displayZscore: "—σ"` quirky formatting.
3. `monthlyHistory` includes historical **score 0** months — may be correct given sparse history but looks harsh in UI sparklines.
